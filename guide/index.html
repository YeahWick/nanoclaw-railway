1 Create Telegram Bot

  • Open Telegram and message @BotFather
  • Send /newbot and follow the prompts
  • Copy the bot token (looks like 123456:ABC-DEF...)
  • Send /setprivacy → choose your bot → Disable (so the bot sees all messages in groups)
  • Add the bot to your Telegram group
Tip: Give your bot a descriptive name and profile picture. This is how it appears in Telegram.

2 Fork & Deploy on Railway

  • Fork the NanoClaw repository on GitHub
  • Go to railway.app/new → Deploy from GitHub Repo
  • Select your forked repo
  • Railway auto-detects the Dockerfile and starts building

3 Configure Environment Variables

In Railway dashboard → your service → Variables tab:

VariableValueRequired
ANTHROPIC_API_KEY Your Anthropic API key Required
TELEGRAM_BOT_TOKEN Token from @BotFather Required
ASSISTANT_NAME Bot display name (default: Andy) Optional
PROCESS_MODE true Set by Dockerfile
TELEGRAM_ONLY true Set by Dockerfile
Security: Never commit API keys to your repository. Always use Railway's Variables tab for secrets.
  • Add ANTHROPIC_API_KEY in Railway Variables
  • Add TELEGRAM_BOT_TOKEN in Railway Variables
  • Optionally set ASSISTANT_NAME

4 Add Persistent Storage

NanoClaw needs persistent storage for its database, group memory, and session history.

  • In Railway dashboard, go to your service → Settings
  • Under Volumes, click + New Volume
  • Set mount path to /data
  • Choose size (1 GB is plenty to start)
Cost: Railway persistent volumes cost $0.25/GB/month. 1 GB is more than enough for most setups.

5 Register Your Main Chat

After deployment, you need to register your Telegram group (or private chat) as the main channel.

Find your chat ID

Send a message in your Telegram group where you added the bot, then check the logs in Railway:

Railway Dashboard → your service → Logs tab

Look for a log line like:

Chat metadata stored: tg:-1001234567890

Register via the bot

For first-time setup, you can register your main chat by sending a message with the trigger word (default: @Andy) in the chat. The simplest approach:

  1. Note the chat JID from the logs (e.g., tg:-1001234567890)
  2. Connect to your Railway service shell (Railway dashboard → service → Shell tab)
  3. Run: 
    node -e "
const { initDatabase, setRegisteredGroup, storeChatMetadata } = require('./dist/db.js');
initDatabase();
storeChatMetadata('tg:YOUR_CHAT_ID', new Date().toISOString(), 'My Chat', 'telegram', true);
setRegisteredGroup('tg:YOUR_CHAT_ID', {
  name: 'Main',
  folder: 'main',
  trigger: '@Andy',
  added_at: new Date().toISOString(),
  requiresTrigger: false,
});
console.log('Main chat registered!');
"
  4. Replace YOUR_CHAT_ID with your actual chat ID (e.g., -1001234567890)
  5. Restart the service for changes to take effect
  • Found chat ID in Railway logs
  • Registered main chat via Railway shell
  • Bot responds to messages

Troubleshooting

Bot doesn't respond to group messages

  • Check that you disabled privacy mode via @BotFather (/setprivacy → Disable)
  • Make sure the chat is registered (check logs for "no channel owns JID")
  • Verify the bot token is correct in Railway Variables

Build fails on Railway

  • Check that your fork includes the Dockerfile in the root
  • Railway should auto-detect Docker builds
  • Check build logs for npm dependency errors

Agent errors (Claude SDK)

  • Verify ANTHROPIC_API_KEY is set correctly
  • Check your API key has sufficient credits
  • Look at process logs in Railway for detailed error messages

Data lost on redeploy

  • Make sure you have a volume mounted at /data
  • Volumes persist across deploys; the container filesystem does not
